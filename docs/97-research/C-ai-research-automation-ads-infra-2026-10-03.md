## A. LLM inference for agents
Purpose: structured, tool-using, Bangla-capable inference behind the model router, with cost tiers.

Candidates (per 1M tokens, input / cached / output):
- **OpenAI**: gpt-5.6-sol $4 / $0.40 / $20; gpt-5.6-terra $2 / $0.20 / $12; gpt-5.6-luna $0.20 / $0.02 / $1.20; gpt-5.4-mini $0.75/$4.50; gpt-5-nano $0.05/$0.40. Batch 50%. Long-context (>272k) doubles input. Prompt caching default, 1,024-token minimum prefix, 30-minute lifetime, cached reads 0.1x. Structured outputs: Responses API `text.format` json_schema strict. Data: no training since Mar 2023; abuse logs up to 30 days; ZDR for /v1/responses etc. needs a qualifying use case + sales approval. Rate limits by spend tier. Bangla: GPT-5 (high) / GPT-5.1 (high) score 91 on the Artificial Analysis Bangla index. BD payability: USD card, prepaid, $300/txn cap manageable.
- **Anthropic**: Opus 5.5 $4/$20 (cache read $0.20), Sonnet 5.5 $2/$10, Sonnet 5 $2/$10, Haiku 4.5 $1/$5, Fable 5.1 $10/$50. Batch 50%, cache write 1.25x (5 min) / 2x (1 h), read 0.1x. Claude 4.7+ tokenizer ~30% more tokens for the same text: compare per task. Structured outputs via `output_format` json_schema. Data: no training on customer content; deleted within 30 days by default; ZDR per org via Sales. Bangla: Claude Opus 4.6 (max) = 92, joint top. Already configured in HQ, off.
- **Google Gemini**: 3.8 Flash $0.75/$3.75 (to $1.50/$7.50 on 1 Jan 2027), 3.5 Flash-Lite $0.30/$2.50, 3.1 Pro $2/$12 (<=200k). Batch 50%. `responseSchema` subset. Free tier content IS used to improve products; paid tier is not. Bangla: Gemini 3.1 Pro Preview = 92, top. BD cards often rejected by Google's Ireland entity (secondary): fallback only.
- **Open-weight via Groq / Together / Fireworks / OpenRouter**: gpt-oss-120b $0.15/$0.60 (secondary); OpenRouter 5.5% card fee (5% USDC), zero prompt logging by default. Groq no retention by default; Together org-level ZDR; Fireworks serverless ZDR. Bangla quality UNVERIFIED; test before routing Bangla traffic.

Recommendation: USE. Primary gpt-5.6-terra for agent/tool tiers, gpt-5.6-luna for classification/extraction, Batch for nightly reconciles. Fallback Anthropic Sonnet 5.5/Haiku 4.5 via the existing router. Gemini paid tier third. Open-weight via OpenRouter as English-only cost/outage fallback. Transport: direct API through the router; no MCP.
Joy prepares: OpenAI prepaid credit; Anthropic credit + spend limit; a 200-prompt Bangla/Banglish eval set; decide whether to request OpenAI ZDR (customer data in prompts suggests yes).
Replacement difficulty: low (router is provider-neutral; schema subsets differ slightly). Risks: mid-year price changes; tokenizer differences distort forecasts; free-tier Gemini trains on data (never route business data there); BD card failures (keep 2 months prepaid); Bangla quality drift between versions (pin ids, re-run eval on upgrade).

## B. Embeddings + vector search
Candidates: OpenAI text-embedding-3-small $0.02/M (MIRACL 44.0), 3-large $0.13/M (MIRACL 54.9, MTEB 64.6), Batch 50%. Voyage: voyage-4-large $0.12/M, voyage-4 $0.06, voyage-4-lite $0.02, 200M free tokens; Bengali coverage UNVERIFIED. Cohere Embed v4: multilingual incl. Bengali, but per-token only via Bedrock/Azure (~$0.12/M secondary): not worth the extra billing. Gemini Embedding 2: $0.20/M, free-tier training caveat. bge-m3 (open, 100+ languages, 8k context): MIRACL avg 70.0 incl. Bengali, IndicQARetrieval Bengali 0.737 (secondary); self-hosting needs an inference container (RAM is the constraint).
pgvector vs managed: pgvector ~640 QPS / 28 ms p50 at 1M vectors vs Qdrant 1,840 QPS / 4 ms (secondary); the playbook store is thousands of chunks, not millions. Qdrant Cloud free 1 GB and Pinecone Starter 2 GB exist but add a second system of record and a USD subscription.
Recommendation: USE pgvector (HNSW, SQL-filtered by scope, transactional). Primary text-embedding-3-large; fallback 3-small; bge-m3 only under a data-residency rule. Store `model_id` + `dim` per row so re-embedding is a job, not a migration. Risks: mixed models in one column; Bengali recall lower than English on every API model (evaluate with 50 Bangla queries); index tuning above ~1M rows.

## H. Workflow automation
- n8n: 2.41.6 stable / 2.42.2 beta; Sustainable Use License permits internal business use, forbids offering it as a paid service; `.ee` files excluded. Queue mode (Redis + workers) in community edition; MCP Server Trigger exposes a workflow as a Streamable HTTP/SSE MCP endpoint; MCP Client Tool node calls external MCP servers; 2.6 added human-in-the-loop for tool calls.
- `durable-workflow/workflow` 2.3.3 (1 Oct 2026, MIT, PHP ^8.1, Laravel ^12.69): embedded durable workflows on Laravel queues/cache/DB, survives worker restarts; successor to the abandoned `laravel-workflow`. Temporal PHP SDK 2.17.1 (Mar 2026): mature but needs RoadRunner workers + a Temporal server; a second runtime on the VPS.
Recommended split: HQ owns every business workflow instance (approval chains, campaign-change requests, document-posting pipelines, shadow-week evaluations) as durable workflows in HQ's Postgres with the Tool Gateway as the only side-effect path; n8n executes idempotent, stateless integration steps (Messenger bot turns, content rendering, third-party polling, scheduled fetches). Contract: HQ → n8n via signed webhook with `run_id` + idempotency key; n8n → HQ via a callback endpoint recording the step result; n8n keeps no business state and no money-capable credentials. HQ engine = BUILD-thin (adopt the MIT package, write only the activities). Temporal: WAIT. Risks: n8n holding workflow truth (standing rule forbids); MCP Server Trigger is public-URL exposed (auth or off); young package (pin versions).

## I. MCP as adapter
Servers that genuinely help as adapters: Meta Ads official (reads/drafts); Brave Search official; GitHub official `github/github-mcp-server` (remote OAuth) for the release/CI agent; Google Workspace MCP (Google's own, preview, Drive/Gmail/Calendar/Chat; no official Sheets server, community `ngs/google-mcp-server`) for the Documents → Drive feature; Postgres: the Anthropic reference server is archived (May 2025); use `crystaldba/postgres-mcp` restricted read-only on a read-only role, or better HQ's own `laravel/mcp` server exposing curated read tools; n8n via MCP Server Trigger (optional, prefer webhooks); WhatsApp: no official MCP; community servers exist; the Cloud API itself is the right surface through a thin adapter, not MCP.
PHP client: `laravel/mcp` 1.0.1 (24 Sep 2026) ships server + client (protocol 2026-07-28, stateless servers, searchable catalogs, OAuth/PKCE); `laravel/ai` 1.0 (23 Sep 2026) drops MCP tools into an agent's tools with approvals; both on `mcp/sdk` 0.8.1 (PHP Foundation + Symfony + Anthropic). Mature enough for adapter use.
Recommendation: ADAPT only: every MCP tool call enters HQ through the Tool Gateway as a capability with its own contract, scope and audit row; MCP servers never hold spend-capable tokens; remote servers with OAuth and short-lived tokens; pin versions; deny write tools by default. Risks: prompt injection via tool results (untrusted), SQL injection in community DB servers (documented on the archived Postgres server), catalog bloat raising token cost.
