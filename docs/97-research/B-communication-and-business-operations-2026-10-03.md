## A. WhatsApp for customer conversations

- **RedX**: merchant API (areas, pickup stores, create parcel, track); token from panel; sandbox flag; no fraud endpoint [S93]. **Paperfly**: official composer package [S94]. **eCourier**: Merchant API v5.1 includes `POST /fraud-status-check` [S50]. **CarryBee**: API v2 referenced by plugin vendors; no public docs [S95]. **Delivery Tiger**: no public API (UNVERIFIED) [S96].
- Fraud aggregators: FraudChecker BD (claims live data from six couriers; ৳100-799/mo; sourcing/consent unstated) [S54]; FraudShield BD, FraudPeek, SMSoft Fraud Check: free lookups, same unexplained sourcing [S97][S98]. - Data protection: Personal Data Protection Act 2026 (Law 63 of 2026; ordinance Nov 2025, amended 5 Feb 2026, enacted 15 Apr 2026): mobile number expressly personal data; processing needs consent or a legitimate ground (contract execution is one); rights to access, rectify, erase, withdraw; fines up to ৳25 lakh (৳50 lakh for significant fiduciaries); National Data Management Authority; some sections bite 18 months after gazette [S99][S100][S101]. Phone-history check only via a courier's own first-party endpoint (Steadfast, eCourier), stated in the privacy notice, store only the decision; **WAIT** on every aggregator until the Authority's SOPs exist. **INTEGRATE** couriers, **WAIT** aggregators. Transport: direct API + webhooks.
Joy prepares: Steadfast merchant account + API keys; Pathao webhook secret; a privacy-notice line on checkout; decide whether HQ may auto-reject on history (recommend: flag, human decides). Risks: Pathao undocumented 429s; scraping gets accounts suspended; PDPA exposure; COD cash reconciliation drift.
